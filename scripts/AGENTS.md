\# AGENTS.md



\## 适用范围

本文件仅适用于 `scripts/` 目录及其子目录。



\## 当前任务定位

这里的任务主要是：

\- 理解代码结构

\- 定位 bug

\- 修复 bug

\- 排查 API / JSON / timeout / logging / roundtable 相关问题

\- 分析脚本行为与论文口径是否一致



\---



\## 代码处理总原则

1\. 先理解，再修改

2\. 优先最小补丁

3\. 不重构无关代码

4\. 不修改无关目录

5\. 任何改动都要说明原因

6\. 修改后要说明如何验证



\---



\## 当前代码应服务的研究主线

代码逻辑原则上应与以下研究流程一致：

1\. 多LLM结构化评分

2\. 离群事件预筛

3\. 论证质量向量评分

4\. 好/坏离群判别

5\. 模型画像与固定权重

6\. 圆桌共识

7\. 最终问题清单提取



如果实际代码与论文设定不一致：

\- 先指出差异

\- 再说明是“论文应改”还是“代码应改”

\- 不要默认代码一定对，也不要默认论文一定对



\---



\## 修 bug 的标准流程

1\. 先描述你认为的问题现象

2\. 指出可能相关的文件

3\. 说明根因分析

4\. 给出最小修改方案

5\. 修改后说明：

&#x20;  - changed files

&#x20;  - 改动点

&#x20;  - 验证方法

&#x20;  - 风险边界



\---



\## 不允许做的事

\- 不要顺手大规模重构

\- 不要修改输出 schema，除非明确要求

\- 不要修改 CLI 参数语义，除非明确要求

\- 不要伪造“本地已跑通”的结论

\- 不要删除日志逻辑，除非明确知道其无用且不影响复现

\- 不要隐式改变实验设定



\---



\## 若涉及 API / 模型调用

必须关注：

\- timeout

\- retry / backoff

\- malformed JSON

\- case-level skip

\- fallback 行为

\- 日志落盘

\- 输出可重放性



这些是研究稳健性的一部分，不要把它们当成无关实现细节删掉。



\---



\## 若涉及解析与中间结果

修改解析逻辑前，先明确：

\- 输入文件格式

\- 输出字段格式

\- 是否被后续分析脚本依赖

\- 是否会影响论文中的结果口径



\---



\## 与论文联动时

如果代码改动会影响：

\- treatment 定义

\- 指标计算

\- 数据过滤

\- 权重计算

\- roundtable 收敛条件

\- final problem list 提取规则



则必须提醒：

“该修改可能影响论文中的方法或结果表述，需要同步核对 paper/ 和 outputs/。”



\---



\## 输出时必须附带

每次完成脚本任务后，必须给出：

1\. 根因分析

2\. changed files

3\. 最小修改说明

4\. 如何验证

5\. 是否可能影响论文结果或已有输出
