# 5 Experimental Design

本章旨在评估本文提出的多LLM协同需求审查框架在真实需求文档上的有效性、稳定性与收敛行为。结合前述研究问题与方法论，实验采用文档内逐条需求分析、文档见配对比较的经验研究设计。实验的核心思想不是比较单个模型的绝对评分高低，而是检验由“离群识别、离群质量判别、模型定权与圆桌共识”构成的完整决策链，是否能够比单模型或简单聚合产生更高质量的团队级问题清单。

## 5.1 实验对象与数据集

本实验的评估对象为多个当前主流的异构大语言模型。基于架构多样性与基础能力的考量，

我们选取了5 个异构 LLM 作为虚拟评审员，分别来自 DeepSeek-Reasoner、Qwen-plus、GPT-5.1、Kimi-k2-0905-preview 和 GLM-5，这种异构型设计旨在真实模拟专家评审团队中不同背景与偏好成员的视角差异。需要指出的是，由于真实 API 环境中可能出现限流、超时或格式不合法输出，系统在实现上允许将失败模型按 case 级别跳过。因此，不同文档上的实际有效模型数可能并不完全一致；本文将这一现象视为系统稳健性的一部分，而非简单地将失败样本剔除。

实验采用的数据集为PURE(PUblic REquirements dataset)【插入】。该数据集的选择基于以下标准：

真实性与复杂性：包含了来自真实工业界或开源软件项目的需求规格说明书（SRS），具有代表性的自然语言歧义与逻辑缺陷。

粒度适配性：数据集支持逐条需求（per-requirement）的拆分，满足本研究对细粒度质量评估的需求。

当前实验选择了 20 份需求文档，覆盖多个应用领域，文档规模从 10 条到 405 条需求不等。所有文档均被转换为统一的 item,text 结构，每条需求作为一个独立评审单元。为保持与方法论一致，本文的最小分析粒度固定为 per-requirement，而非文档级整体评分。

## 5.2 实验设计与对照设置

为回答研究问题，本研究采用组内对照设计（Within-subject design）。同一份需求文档将在以下四种不同的处理条件（Treatments）下被重复评估：

Single-LLM（单一模型）：由单个 LLM 独立完成四维评分与问题输出，作为最基础的性能下界。

Equal-Weight Aggregation（等权聚合）：多模型独立评分后，不引入离群判别，直接进行等权聚合，用于评估“单纯引入多模型”带来的基线提升。

Roundtable w/o Weighting（无权重圆桌）：保留多轮圆桌讨论机制，但在讨论中所有模型均保持等权参与，旨在隔离“多轮博弈”的独立贡献。

Full Method（完整方法）：采用本文提出的“离群识别 + 论证质量判别 + 动态模型定权 + 条目级圆桌共识”全流程决策链。

## 5.3 变量、Ground Truth与度量指标

### 5.3.1 评价单元与Ground Truth

本系统需要判断每条需求在四种缺陷类型上是否存在问题。因此，评价的最小单元不是整条需求或原始评分值，而是将需求缺陷识别任务建模为(item ,type)粒度的多标签判别问题，其中type∈{U,A,C,V}。为构建高可靠的Ground Truth，由两名具备 3 年以上需求工程经验的专家对全部二元组进行独立盲标；针对分歧项，通过第三名资深专家引入讨论仲裁。专家间的初始标注一致性采用 Cohen'sKappa 或 Krippendorff's α 进行严谨报告。

### 5.3.2 变量与度量指标定义

根据研究问题，我们定义了以下核心度量指标：

针对评分差异与离群特征（RQ1）：·绝对偏差（abs_deviation）：单一模型评分偏离该条目群体中位数的绝对值。·模型间信度：基于序数性 Krippendorff's α 度量多模型初始评分的趋同程度。

针对论证质量与定权（RQ2 & RQ3）：·论证质量分（Q）：连续变量Q∈[0,1]，量化离群事件中文本证据的逻辑深度与可执行性。·硬性失败率（Hard Fail Rate）：证据缺失或维度错配的离群事件占比。

针对最终输出质量与收敛性（RQ4）：·Macro−F1（主指标）：由于U/A/C/V四类缺陷在真实文档中分布极度不均衡，采用文档级Macro−F1作为核心性能指标（先计算各类别F1再取无权平均），以防少数类表现被掩盖。同时辅以Precision与Recall。·集合Jaccard相似度（Issue−set Jaccard）：度量相邻圆桌轮次间候选缺陷集合的重合度。

### 5.3.3 控制变量与参数设置

为降低内部效度威胁，所有对照组共享相同的输入模板、解析脚本与系统配置。核心超参数我们固定为：离群阈值δ=2，好离群阈值τgood=0.60，坏离群阈值τbad=0.30，惩罚系数λ=1.5，放大系数β=1.0，每轮讨论侯选数topK=10，最大讨论轮次rounds=2，最终提取阈值θratio=0.6。

## 5.4 数据收集与系统稳健性控制

在真实API环境下采集多模型输出时，不可避免会面临限流、网络超时或模型输出非严格JSON格式等问题。本实证研究将此类现象显式纳入系统稳健性考量，而非简单剔除失败样本。

数据收集系统部署了指数退避重试与容错降级机制。若某模型在特定条目上历经最大重试后仍失败，系统仅在当前 case 中禁用该模型，其余成功响应的模型继续完成后续流程。这种设计真实反映了本文方法在“部分成员缺席”情况下的鲁棒性。所有 API 交互日志、坏 JSON 日志与圆桌轮次历史均被版本化落盘，确保实验数据的绝对可复查与可重放。

## 5.5 数据分析方法

统计分析严格以“需求文档”为基本比较单元，避免将不同文档条目直接混合导致的辛普森悖论（Simpson's Paradox）。针对各 RQ，分析计划如下：

解答RQ1（差异结构）：计算多模型在各维度的中位数与四分位距（IQR）。采用 Kruskal−Wallis H检验 分析不同缺陷维度（U/A/C/V）触发离群事件（abs_deviation≥δ）的频率是否存在显著的统计学差异。

解答RQ2（判别有效性）：提取被判定为“好离群”与“坏离群”的事件特征。采用 Mann−Whitney U检验 分析两者在Q分数分布及文本证据长度等外在属性上是否实现显著分化，验证判别机制的区分度。

解答RQ3（模型定权验证）：对比 Equal−Weight 基线与本文基于 (Gr,Br) 构建的动态定权策略在单轮次下的指标差异。采用配对 Wilcoxon 符号秩检验 （Wilcoxon Signed−Rank Test）检验 Macro−F1 的提升显著性，并计算 Cliff'sDelta 作为非参数效应量（Effect Size），以评估该赋权策略在实际工程中的增益幅度。

解答RQ4（圆桌机制与最终性能）：对于多个处理条件（Single−LLM vs.Equal−Weight vs.Roundtable w/o Weight vs.Full Method）的整体性能对比，采用 Friedman 检验 进行全局差异性分析；若显著，则使用 Holm 校正 （Holm−Bonferroni method） 进行事后多重比较分析（Post−hoc analysis）。同时，绘制随轮次递增的 Jaccard 相似度曲线与分数波动衰减图，直观展示系统的数学收敛行为。
