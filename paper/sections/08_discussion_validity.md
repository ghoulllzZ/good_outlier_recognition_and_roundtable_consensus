# 7 Validity Threats and Discussion

## 7.1 Validity Threats

### 7.1.1 Construct Validity

建构效度主要涉及理论概念与实际度量指标之间的匹配程度。本研究的核心威胁在于论证质量（Q）分数的计算公式、六维特征的定义以及硬性否决（Hard Fail）机制的设定。这些规则与经验阈值（如 τgood=0.60,δ=2）可能存在一定的主观偏置。

Mitigation:本文的维度定义（U/A/C/V）严格映射自经典的 IEEE 需求规格说明标准与已有的实证软件工程分类法（DIM_MAP）。对于 Q 分数的量化，我们避免了复杂的非线性赋权，而是采用简单的均匀归一化并辅以底线阻断（Hard Fail），以此剥离过度拟合的风险。同时，实验设计中的消融对比（对比无定权圆桌与本文完整方法）已侧面证明了当前参数设置足以在实际任务中产生显著的区分度。

### 7.1.2 Internal Validity

内部效度关注实验执行中可能干扰因果关系的实现细节。核心威胁来自真实 API 服务的不稳定性。在实验中，限流、超时或非法的 JSON 输出会导致部分模型在特定条目上被跳过。这意味着不同文档或条目上的实际有效模型数（n_raters）并不完全一致，这可能会对模型间的公平比较以及文档间的横向对比造成干扰。

其次，当前实验参数如离群阈值、好/坏离群阈值、惩罚系数、Top-K 和最大轮次等均基于经验设置。虽然这些参数在所有文档中保持一致，有利于内部一致性，但它们仍然可能影响最终问题清单的规模与结构。特别是当文档本身的缺陷密度和领域差异较大时，同一组固定参数未必总是最优。

Mitigation:我们将 API 不稳定性显式纳入了系统的稳健性考量，而非视其为必须剔除的噪声。系统部署了重试与case级隔离机制：当某模型彻底失败时，系统仅在该需求条目上禁用该模型，其余模型继续完成圆桌。这种设计真实反映了本文方法在“评审团队部分成员缺席”情况下的鲁棒性。实验结果以文档级 Macro-F1 汇总，有效稀释了单一条目请求丢失带来的随机影响。

### 7.1.3 External Validity

外部效度涉及研究结论向其他场景或未来模型泛化的能力。首先，PURE 数据集虽然真实，但主要代表传统的系统规格说明书（SRS），可能无法直接推演至高度敏捷开发中的用户故事（User Stories）或特定合规领域（如医疗软件）。其次，实验选定的 5 款异构 LLM 具有时效性，随着基础模型能力的快速迭代，当前的离群结构和权重分配分布在未来可能会发生漂移。

Mitigation:在文档选择上，我们抽取了覆盖不同领域、规模（10至405条）与缺陷密度的样本，以证明该框架不依赖于单一上下文。在模型层面，本研究验证的是“基于价值判别的动态定权与圆桌框架”这一方法论的可行性，而非对当前几款模型的永久性排序。该框架在理论上与底层的具体模型解耦，具备向新一代模型生态无缝迁移的基础潜力。

### 7.1.4 Conclusion Validity

结论效度关注统计分析是否足以支撑研究推论。主要威胁在于文档间异质性（如规模、缺陷密度差异极大）带来的统计偏差。若直接将所有需求条目混合计算 p 值，极易引发辛普森悖论（Simpson's Paradox）。

Mitigation:在统计设计上，我们严格采用“Document”作为配对比较的 Block 单元，使用了鲁棒的非参数统计方法（如 Friedman 检验与配对 Wilcoxon 符号秩检验）并强制报告非参数效应量（Cliff's Delta），以规避分布异质性带来的误判。

## 7.2 Discussion

综合上述结果与威胁分析，本文当前最重要的启示有三点。第一，在多 LLM 需求审查中，“少数派意见”不是应被直接抹平的噪声，而是应被进一步审查的潜在信息源；关键不在于是否偏离共识，而在于偏离是否具备高质量证据与可执行改写。第二，模型定权不应被理解为对模型能力的静态排序，而应被理解为一种文档内、任务内的证据驱动型信任分配机制。第三，圆桌共识的主要价值不是让模型的数值评分完全一致，而是帮助系统在有限轮次内稳定形成更紧凑、更可操作的问题集合。总体上，当前结果支持本文方法作为一种“从分歧到共识”的需求质量审查框架具有可行性；而上述有效性威胁则提醒我们，应将其视为一个具备明确工程价值和研究潜力、但仍需在更大规模对照实验中进一步验证的方法体系。
